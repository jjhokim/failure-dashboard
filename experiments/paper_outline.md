## 0. 핵심 메시지 (한 문장)

> 유도무기 정비기록에서 공통원인 후보를 탐지·우선순위화하는 스크리닝 파이프라인을
> 구현하고, **순환검증을 차단한 합성데이터 설계**로 내적 타당도를 검증했다.
> 채널 융합의 이점은 **공통원인 신호의 시간 분산 정도에 조건부**임을 밝혔다.

### 주장하는 것 / 주장하지 않는 것 (서론·결론에 명시)

| 주장한다 | 주장하지 않는다 |
|---|---|
| 주입한 공통원인 구조의 **회수 정확도**(내적 타당도) | 고장 원인의 **인과 판정** (FMECA·FTA의 몫) |
| 채널 융합 이점의 **조건부성** | **실운용 성능** (합성데이터 기반) |
| 순환검증 차단 **설계 방법론** | Ao 조기경보·CAI 등 후속 기능 |

## 1. 논문 구성 제안

### 1장 서론
- 문제: 3제대에 흩어진 정비기록에서 공통원인 후보를 사람이 찾기 어렵다.
- 기존 접근의 한계: 키워드 검색·파레토는 표현 편차와 구조·시간 맥락을 못 다룬다.
- 기여 3가지:
  1. 3채널(의미·구조·시간) 융합 기반 공통원인 스크리닝 파이프라인
  2. **순환검증을 차단한 합성 평가 설계** (R1~R3) — 본 논문의 방법론적 핵심
  3. 사전등록 기반 검증과, 그로부터 드러난 **조건부 결론**

### 2장 관련 연구
- 공통원인 고장(CCF) 분석: NUREG/CR-6268, NUREG/CR-5485
  → **CCF 시간 창이 고정 상수가 아니라 '선택값'** 이라는 점을 인용 (5장 한계와 연결)
- RAM 지표: 방사청 「무기체계 RAM 업무지침」(2018)
- 문장 임베딩 군집화: KoSBERT, HDBSCAN

### 3장 방법
1. **데이터 스키마·지표** (§3.1)
   - 정비 3제대, LCN 계층, effect_class(EFF/NEFF), 운용시간 기반 분모
   - Ai = MTBF/(MTBF+MTTR), Ao는 MDT/ALDT 결측 시 **산출하지 않음**
   - MTTR은 Kaplan-Meier로 우측절단 보정 (진행 중 수리건 편입)
2. **탐지 파이프라인** (§3.2) — 그림: 아키텍처 다이어그램(미작성)
   - 의미: KoSBERT 코사인 거리 / 구조: LCN 트리 경로거리 / 시간: 1−exp(−|Δt|/τ)
   - min-max 정규화 후 가중합 → HDBSCAN(precomputed)
3. **우선순위화** (§3.3)
   - S = w_size·규모 + w_trend·추세 + w_crit·치명도 (각 z-표준화)
   - 치명도는 **관측치 대체값만** 사용 (λ_obs, β·α≈EFF 비율)
4. **합성 평가 설계 — 순환검증 차단** (§3.4) ★ 핵심 절
   - R1: 라벨→물리상태는 **규칙 기반 코드만**. 문장 생성기는 `cluster_id`를 받지 않음
   - R2: 생성기와 탐지기가 문자열·임베딩 공간·사전을 공유하지 않음
   - R3: BIT는 조인까지만, 탐지 채널로 융합하지 않음
   - 라벨 누출 검사 3종(토큰 출현률·TF-IDF 예측·어휘 Jaccard)

### 4장 실험
- **4.1 사전등록** — 합격기준 C1~C6를 실행 전 확정(R5), 8시드 mean±std(R4)
- **4.2 주 결과 (legacy 생성기)**
  - 표 1 / 그림 1: δ별 ARI → **C1·C2·C3 충족**
  - 표 2 / 그림 2: 채널 ablation → **C4 불충족** (융합 0.736 < 시간 0.853)
  - C5 충족: ρ 0.526, 95% CI [0.267, 0.760], P@5 0.900
- **4.3 후속 분석 — C4 불합격의 원인 규명**
  - 표 3 / 그림 3: legacy vs floor
  - H1 기각: 가중치 탐색 최적해가 `(0,0,1)`로 수렴 → 가중치 문제가 아님
  - H2 지지: 밀집폭 완화 시 융합 0.938 > 시간 0.786, CI [0.090, 0.236]
  - H4-a 충족: floor에서는 탐색이 `(0.5,0.25,0.25)`로 **세 채널 모두 유지**
- **4.4 민감도 분석** — 그림 5 / 표 5: 교차점 2~3.65일
- **4.5 우선순위화 축 진단** — 그림 4 / 표 4: 잔차화(S1)가 오히려 ρ 악화
  → 규모~치명도 상관은 **허위 중복이 아니라 신호**

### 5장 논의·한계
1. **결론의 조건부성** (가장 중요)
2. 시간 밀집폭은 **실측 근거가 없는 설계값** — 1일·3.65일 모두 임의
3. Detection Delay 지표가 채널 품질을 변별하지 못함 (방법론적 발견)
4. 조기경보가 아니라 **사후 스크리닝** 도구 (δ=1.0에서도 56%만, 평균 269/600건)
5. 합성데이터 기반, 실운용 일반화 불가

## 4. 작성 시 반드시 지킬 것

1. **주 결과는 legacy**(C4 불합격 포함). floor는 **사전등록된 후속 분석**으로 병기.
   결과가 좋다고 floor를 주 결과로 바꾸면 사전등록의 의미가 사라진다.
2. **단일 시드 수치를 쓰지 않는다**(R4). 파일럿 수치도 성능 근거로 인용하지 않는다.
3. 사후에 알게 된 사실로 **기준을 소급 변경했다는 인상을 주지 않는다.**
   C4는 불합격으로 두고, 원인 규명은 별도 절로 분리한다.
4. C6에 대해 사전등록의 근거가 틀렸었다는 점을 **투명하게 기술**한다
   (단일 시드 파일럿으로 축 상관을 추정한 것이 오류였음 → R4의 적용 범위 확장).
5. "AI"라는 표현은 KoSBERT/HDBSCAN 파이프라인에만 쓴다(R7).
   통계 지표(Ai·MTBF·MTTR) 산출을 AI라고 부르지 않는다.
6. 모든 성능 주장에 **"합성데이터 기준"** 을 붙인다.
